| 項目 | 内容 |

| 参照 | [2026-11-20-first-implementation.md](./2026-11-20-first-implementation.md)、[slide-ir.md](../slide-ir.md)、[fix-instructions.md](../fix-instructions.md) |

## 1. 方針

- **スライドの原稿は、作業メモ 1 つだけ。** LT の内容を作業メモ（`slide-demo/memo.md`）に書き、`text_to_page_grouper()` と `page_to_slideir_page()` を通して、スライドにする。手でスライドを整えない
- **`target.py` が不完全であることを隠さない。** うまく変換できなかったページは、そのことがわかる形で表示する。崩れたスライドそのものが、TGDD の「考慮漏れ」の実例になる
- **発表が止まらないことを最優先にする。** 変換がどう失敗しても、ページは必ず表示され、原文をいつでも見られる
- **デモのために `target.py` を直さない。** 作業メモは、修正のルーチンにもテストデータの生成のルーチンにも読ませない。スライドが良くなるのは、テストガチャで見つかった考慮漏れが直った結果だけにする

## 2. できあがるもの

手元でビルドして、次の 2 つをつくる（`uv run python slide-demo/build.py`）。GitHub Pages では公開しない。

| 出力 | 内容 |
|---|---|
| `slide-demo/dist/slides/<版>.ltool` | SlideIR の生成結果。`target.py` の版ごとに 1 ファイル（5.3） |
| `slide-demo/dist/index.html` | `.ltool` を読んで表示する、ブラウザで開く 1 つの HTML |

生成（作業メモ → `.ltool`）と表示（`.ltool` → HTML）を、ファイルを境に分ける。`.ltool` は SlideIR のドキュメントなので、LTooL でもそのまま読める。版どうしの `.ltool` の差分を取れば、修正で何が変わったかを XML で確かめられる。

### 2.1 画面

```
┌──────────────────────────────────────────────┐
│                                              │
│              スライド（16:9）                  │
│                                              │
├──────────────────────────────────────────────┤
│ 3 / 12   v5 (11/21 13:30) ▸ 最新   テスト 41/60 通過   ⚠ 未解釈の記号 │
└──────────────────────────────────────────────┘
```

- 上: 生成されたスライド 1 ページ
- 下: 状態の帯。ページ番号、表示中の `target.py` の版、その版のテストガチャの通過数、このページの注意（3 章）

### 2.2 操作

| キー | 動作 |
|---|---|
| `→` `←`（クリック・スワイプ） | ページ送り |
| `s` | 原文の表示を切り替える。スライドの左に、そのページの元になった作業メモの行を並べて出す |
| `x` | そのページの SlideIR の XML を表示する |
| `↑` `↓` | `target.py` の版を切り替える（古い版 ↔ 新しい版）。同じ作業メモが、版によってどう変わるかを見せる |
| `g` | 版ごとの推移の画面（2.3）を開く |
| `f` | 全画面 |

URL で版とページを指定できる（`?v=<コミット>#5`）。本番で特定の版に固定して話すときに使う（4.3）。

### 2.3 版ごとの推移

`target.py` を変更したコミットを、古い順に 1 つの版とする。版ごとに次の値を並べたグラフと表を出す。

| 値 | 内容 |
|---|---|
| テストガチャの通過数 | その版の `target.py` で、**現在の**すべてのテストデータを実行した結果。版どうしを同じ問題で比べる |
| ページ数 | 作業メモから作られたページの数 |
| 注意のあるページ数 | 3 章の注意が 1 つ以上付いたページの数 |
| 原文の再現率 | 作業メモの文字のうち、スライドに現れた割合（3.2） |

テストデータは毎時増えるので、通過数は作り直すたびに変わる。「問題が増えても通過率が上がっていく」ことが見せたい点である。

## 3. 思うように表示できない場合の見せ方

失敗を 3 つの段階に分け、段階ごとに見せ方を決める。どの段階でも、ページは飛ばさず必ず表示する。

### 3.1 段階と見せ方

| 段階 | 起きること | 検出の方法 | 見せ方 |
|---|---|---|---|
| A. 変換できない | 例外が出る、時間内に終わらない、戻り値が文字列でない | 実行時に捕まえる | **代わりのスライド**を出す。原文を等幅の文字でそのまま載せ、上に「変換できませんでした」と例外の種類を出す |
| B. SlideIR として正しくない | 整形式の XML でない、ページの型の境界に合わない、知らない要素がある | `validate_page_xml()`（テストデータの検査と同じもの） | A と同じ代わりのスライド。検査で見つかった問題を 1 行出す |
| C. 正しい形だが、意図と違う | 記号が文字として残る、行が抜ける、ページの分け方が違う | 3.2 の目安で検出する。検出できないものもある | スライドはそのまま表示し、状態の帯に注意を出す。`s` で原文と見比べられる |

分割（`text_to_page_grouper()`）が失敗した場合（例外、戻り値が文字列の配列でない）は、作業メモ全体を 1 ページとして A の代わりのスライドにする。

### 3.2 「意図と違う」の目安

正解のスライドは用意しない（用意すると、スライドを手で書くのと同じになる）。入力と出力だけから機械的にわかることを、注意として出す。

| 注意 | 条件 |
|---|---|
| 未解釈の記号 | スライドの文字列に、記法の記号が残っている（行頭の `#`・`-`・`*`・`1.`、`**`、`` ` ``、`![`、`](` など） |
| 原文の抜け | そのページの原文の文字（記号と空白を除く）のうち、スライドに現れない文字がある。割合を出す（原文の再現率） |
| 原文にない文字 | スライドに、原文にない文字がある |
| はみ出し | 表示したときに、内容がスライドの枠に収まらない（ブラウザ側で検出する） |
| 行き場のない行 | 作業メモの行のうち、どのページにも入らなかった行がある（分割の結果を作業メモと突き合わせる）。最後のページの後に「どのページにも入らなかった行」のページを足して、その行を載せる |

注意は「おかしいかもしれない」という目安で、考慮漏れの判定ではない。テストガチャの結果（2.3）と役割を分ける。

### 3.3 はみ出しの扱い

分割がうまくいかないと、1 ページに大量の行が入る。切り捨てると何が起きたかわからないので、次のようにする。

- 文字を一定の大きさまで自動で縮める
- それでも収まらなければ、縮めた状態で表示し、下端をぼかして「はみ出し」の注意を出す。スクロールで続きを見られる

## 4. 本番で話せることの保証

### 4.1 原文はいつでも見られる

どのページでも `s` で原文を出せる。スライドが崩れていても、原文を見せながら話せる。

### 4.2 作り直しに失敗しても、前のスライドは残る

ビルドは手元で行う。本番の前に `git pull` してビルドし、できた `index.html` を確認してから使う。ビルドが失敗したときは、前につくった `dist/` をそのまま使う。

### 4.3 版を固定できる

- すべての版のスライドを 1 つの HTML に入れる。`?v=<コミット>` で、どの版でも表示できる
- 本番の直前に修正がマージされて表示が変わっても、確認済みの版に固定して話せる
- HTML は 1 ファイルで完結させ、ローカルのファイルとして開く（外部の画像を除く。5.5）

## 5. 仕組み

### 5.1 構成

```
slide-demo/
├── memo.md            LT の原稿（作業メモ）。人が書く
├── build.py           ビルドの入口
├── versions.py        git の履歴から target.py の版を取り出し、版ごとに実行する
├── runner.py          1 つの版の target.py を、別のプロセスで実行する
├── ltool.py           ページの XML を SlideIR のドキュメントにまとめ、.ltool に書く・読む
├── render.py          .ltool のページを HTML にする
├── checks.py          3.2 の注意の検出
├── template.html      画面（スライドの枠、状態の帯、操作の JavaScript、CSS）
└── dist/              出力（git には入れない）
    ├── slides/<版>.ltool         SlideIR の生成結果
    ├── slides/<版>.report.json   生成の記録（原文との対応、変換できなかったページ、注意）
    └── index.html
tests/
└── test_slide_demo.py
```

### 5.2 ビルドの流れ

1. `git log --follow --format=... -- target.py` で、`target.py` を変更したコミットを古い順に並べる（`main` のもの）。これが版の一覧になる
2. 版ごとに、`git show <コミット>:target.py` で取り出した `target.py` を `runner.py` で実行する
    - `memo.md` を分割し、ページごとに変換する（`id` は、`# ` で始まるページが `cover`、ほかは `p1`・`p2`・…）
    - すべてのテストデータでテストガチャを実行し、通過数を得る
3. ページごとに 3.1 の段階を判定し、版ごとに `.ltool` と記録（`.report.json`）を書き出す（5.3）
4. `.ltool` と記録を読み、`render.py` で HTML にする（A・B は代わりのスライド）。`checks.py` で注意を付ける
5. すべての版の結果を `template.html` に埋め込み、`dist/index.html` に書き出す

1〜3 が生成、4〜5 が表示で、表示は `.ltool` と記録だけを入力にする（`target.py` を呼ばない）。

### 5.3 `.ltool` と記録（`ltool.py`）

**`.ltool`** は、ページプールのみの SlideIR のドキュメント（XML・UTF-8）。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<SlideIR xmlns="https://docs.ltool.io/ns/slide-ir" version="0.1">
  <PagePool>
    <CoverPage id="cover">…</CoverPage>
    <GeneralPage id="p1">…</GeneralPage>
  </PagePool>
</SlideIR>
```

- `page_to_slideir_page()` が返す名前空間なしの断片に、ここで名前空間を付けて `<PagePool>` に入れる。ページは作業メモに現れた順に並べる
- **正しいページだけを入れる。** 変換できなかったページ（段階 A）と、SlideIR として正しくないページ（段階 B）は入れない。`.ltool` は、いつでも正しい SlideIR のドキュメントにする
- ドキュメントとしての規則も確かめる。`id` が重複したページと、2 つ目以降の `CoverPage` は段階 B として扱い、入れない
- ファイル名は `<連番>-<コミットの短い ID>.ltool`（例: `03-fd1683d.ltool`）。最新の版は `latest.ltool` としても置く

**記録（`.report.json`）** は、`.ltool` に入らない情報を持つ。表示と 2.3 の推移は、これを使う。

| 項目 | 内容 |
|---|---|
| 版 | コミット、日時、コミットのメッセージ、テストガチャの通過数 |
| ページごと | 原文、段階（正常・A・B）、`.ltool` の中の `id`（正常のとき）、`target.py` の戻り値と例外・検査の問題（A・B のとき）、注意（3.2） |
| 行き場のない行 | どのページにも入らなかった作業メモの行 |

ページの順番は記録が持つ。`.ltool` に入らなかったページも、記録の順番どおりに代わりのスライドとして表示する。

### 5.4 古い版の実行（`runner.py`）

- 版ごとに別のプロセスで実行し、時間の上限（1 回の呼び出しにつき数秒）を付ける。例外や無限ループがあっても、ビルドは止まらない
- 結果は JSON で受け取る（ページごとの原文、戻り値、例外の種類とメッセージ）
- 関数がない、引数の形が違うなど、呼び出せない版は「変換できない」（段階 A）として扱う

### 5.5 表示（`render.py` と `template.html`）

- `.ltool` と記録を読んで表示する。XML から HTML への変換は、ビルドのときに Python で行う。ブラウザ側の JavaScript は、ページ送りと表示の切り替えだけを受け持つ
- レイアウトは [slide-ir.md](../slide-ir.md) の 2.2 のとおり

    | 型 | レイアウト |
    |---|---|
    | `CoverPage` | 題名・副題を中央に置く |
    | `HeadingPage` | 見出しを中央に大きく置く |
    | `GeneralPage` | 上に見出し、その下に本文を並べる |
    | `BodyPage` | 本文を並べる |
    | `FigurePage` | 図を中央に大きく置く |

- 文字列はすべてエスケープして埋め込む。リンクと画像の URL は `http`・`https` だけを通す
- 画像は URL のまま読み込む。本番の会場でネットワークが使えないと表示されないので、LT で使う画像はリポジトリに置き、公開した URL を作業メモに書く

### 5.6 ビルドの実行

```bash
git pull origin main
uv run python slide-demo/build.py     # slide-demo/dist/index.html ができる
```

- 版は、手元の `main` の履歴から取る。修正のプルリクエストをマージしたら、`git pull` してからビルドする
- 作業ツリーの `target.py` がコミットと違うときは、「作業中」の版として最後に足す
- GitHub Actions では、`ci.yml` でテストだけを実行する。スライドの公開はしない

## 6. 修正のルーチンとの関係

- `docs/fix-instructions.md` と `docs/test-data-generation.md` に、「`slide-demo/memo.md` を読まない」を足す。デモの原稿に合わせた修正や、原稿をなぞったテストデータを防ぐ
- `slide-demo/` は、修正のルーチンが変更してよいファイルに含めない（今の指示のままで含まれない）
- `target.py` の関数の名前と引数は、版をまたいで変えない。変えると、古い版との比較ができなくなる。`fix-instructions.md` に足す

## 7. テスト（`tests/test_slide_demo.py`）

`ci.yml` で実行する。

| 対象 | 確かめること |
|---|---|
| `ltool.py` | 断片に名前空間が付き、正しいページだけが作業メモの順に入る。A・B のページ、`id` の重複、2 つ目の表紙は入らない。書いた `.ltool` を読み戻せる |
| `render.py` | 5 種類のページ、ブロック（文章・箇条書きの入れ子・番号付き・表）、図、インラインが HTML になる。`<`・`&` がエスケープされる。`javascript:` の URL がリンクにならない |
| 段階の判定 | 例外・時間切れ・文字列でない戻り値は A、整形式でない XML・境界に合わないページは B になり、どちらも代わりのスライドに原文が載る |
| `checks.py` | 未解釈の記号、原文の抜け、原文にない文字、行き場のない行を検出する。問題のないページには注意が付かない |
| `runner.py` | 例外を出す版、終わらない版、関数がない版があっても、ほかの版の結果が得られる |
| ビルド全体 | 一時的な git リポジトリに `target.py` の版を 3 つ作り、ビルドが成功して、3 つの版と全ページが HTML に含まれる |

## 10. リスク

| リスク | 対応 |
|---|---|
| 本番の直前のマージで、スライドが崩れる | 4.3 の版の固定。確認済みの版の URL を控えておく |
| 修正が進んでも、作業メモのスライドが良くならない（テストデータが、原稿で使う書き方に当たらない） | 原稿は読ませない方針は変えない。良くならないこと自体を、偶然に頼る「ガチャ」の性質として話す。3.2 の注意で、どこが崩れているかは示せる |
| 3.2 の目安が、正しいスライドに注意を出す（誤検出） | 注意は目安と明示する。誤検出が多い項目は、条件を絞るか外す |
| 古い版の `target.py` を実行できない | 5.3 の別のプロセスと時間の上限。呼び出せない版は段階 A として表示する |
