# テストデータの生成の指示

Claude のスケジュールタスク（毎時 00 分）が、この文書に従ってテストデータを 1 ファイル作る。

## 1. やること

1. 日本時間の現在の日時から、名前を決める

    ```bash
    STAMP=$(TZ=Asia/Tokyo date +%Y-%m-%d-%H)   # 例: 2026-11-21-09
    ```

    - ファイル: `tests/test_data/$STAMP.json`
    - ブランチ: `claude-$STAMP`
2. `origin/main` を取得する。同じ名前のファイルかブランチがすでにあれば、何もせずに終わる
3. 2 章の資料を読む
4. 3〜5 章に従って、テストデータを 10 件作る
5. 検査する。通るまで直す

    ```bash
    uv sync --locked
    uv run python tools/validate_test_data.py tests/test_data/$STAMP.json
    ```

6. `main` から `claude-$STAMP` ブランチを作り、**そのファイル 1 つだけ**を追加してコミットし、push する
7. `main` に向けたプルリクエストを作る
    - タイトル: `テストデータ $STAMP`
    - 本文: テストデータごとの狙い（6 章）

プルリクエストは、GitHub Actions が検査して自動でマージする。自分ではマージしない。

## 3. 変えてよいもの

- 追加してよいのは `tests/test_data/$STAMP.json` だけ
- ほかのファイル（過去のテストデータ、コード、ワークフロー、文書）は変更・削除しない。変更が混ざると、プルリクエストは自動で止まる
- 検査が通らないときに、検査のツールやスキーマのほうを直さない

## 4. 入力（`input_text`）の作り方

LT の準備中に書いた作業メモを想定する。題材は毎回変える（技術の話、失敗談、ツールの紹介、振り返りなど）。

10 件の内訳の目安:

| 件数 | 内容 |
|---|---|
| 3 件 | 仕様どおりの書き方。ページの型（Cover・Heading・General・Body・Figure）と要素の組み合わせを変える |
| 5 件 | 仕様にある記法の揺れ・境界。1 件につき観点を 1 つに絞る |
| 2 件 | 仕様にない書き方。人が作業メモに書きそうなもの |

観点の例（これに限らない。過去のテストデータにない観点を優先する）:

- 記号の揺れ: 全角の `＃`・`－`・全角空白、`*` や `+` の箇条書き、`##` の後に空白がない、見出しの末尾の `#`
- 字下げの揺れ: タブ、空白 4 つ、段が飛ぶ入れ子、見出しの行頭の空白
- 空行: 見出しと本文の間、箇条書きの途中、連続する空行、末尾に改行がない、CRLF
- 見出し: `#` が複数ある、`#` が途中にある、`###` 以下の見出し、見出しがない、見出しの中の太字やリンク
- インライン: 太字・斜体・コード・リンク・打ち消し線、入れ子、閉じていない記号、URL だけの文字列
- 図: 代替テキストが空、図が続く、図と文字が同じ行にある、箇条書きの中の図、画像以外の URL
- 本文: 番号付きリスト、表、コードブロック（中に `## ` がある）、引用、水平線、長い段落
- そのほか: 空の入力、空白だけの入力、絵文字、とても長い行、HTML のタグ、`<` `&` などの記号

## 5. 期待値の書き方

期待値は、作業メモを書いた人が意図したスライドにする。仕様（計画書の 2 章と slide-ir.md）で決まることは、仕様のとおりに書く。

### 5.1 `expected_page_group`

- ページごとのテキスト。`input_text` の行をそのまま使い、行の中身を書き換えない
- 前後の空行と行末の空白は含めない
- ページにならない入力（空の入力など）は、空の配列にする

### 5.2 `expected_slideir_page`

- `expected_page_group` と同じ順序・同じ数にする
- 名前空間なしの、ページの要素 1 つの XML。空白や改行を挟まずに 1 行で書く
- `id` は、表紙が `cover`、ほかは現れた順に `p1`・`p2`・…。`order` は付けない
- 文字列は必ず `<Str>` に入れ、`&`・`<`・`>` はエスケープする

| 作業メモ | XML |
|---|---|
| `# 題名` | `<CoverPage id="cover"><title>…</title></CoverPage>` |
| `## 見出し` だけ | `<HeadingPage id="p1"><title>…</title></HeadingPage>` |
| `## 見出し` と本文 | `<GeneralPage id="p1"><title>…</title><blocks>…</blocks></GeneralPage>` |
| 見出しがなく、図 1 つだけ | `<FigurePage id="p1"><ImageFigure src="…" alt="…" /></FigurePage>` |
| 見出しがなく、それ以外の本文 | `<BodyPage id="p1"><blocks>…</blocks></BodyPage>` |
| 段落（1 行） | `<TextBlock><Paragraph>…</Paragraph></TextBlock>` を `<blocks>` の直下に置く |
| `- 箇条書き` | `<Cluster marker="true">` の中に、項目ごとの `<TextBlock>`。続く項目は同じ `<Cluster>` に入れる |
| 字下げした箇条書き | 親の `<Cluster>` の中に `<Cluster marker="true">` を入れ子にする |
| `1. 番号付き` | `<Cluster ordered="true" marker="true">` |
| `![代替](URL)` だけの行 | `<ImageFigure src="URL" alt="代替" />`。代替テキストが空なら `alt` を省く |
| `**太字**` | `<Strong><Str>太字</Str></Strong>` |
| `*斜体*` | `<Em><Str>斜体</Str></Em>` |
| `~~打ち消し~~` | `<Strike><Str>打ち消し</Str></Strike>` |
| `` `コード` `` | `<Code>コード</Code>` |
| `[文字](URL)` | `<Anchor href="URL"><Str>文字</Str></Anchor>` |

### 5.3 仕様にない書き方の期待値

- 人が見て「こう書いたなら、こう表示したいはず」と言える期待値にする。たとえば全角の `＃＃` で始まる行は、見出しとして扱うのが自然である
- 人によって判断が分かれる入力は避ける。どちらとも言える入力では、失敗しても考慮漏れかどうかを決められない
- slide-ir.md にない要素や属性を作らない。表せない書き方（数式など）は、記法の文字列のまま `<Str>` に入れる

## 6. プルリクエストの本文

テストデータは項目を増やせないので、狙いは本文に書く。失敗したときに、考慮漏れか期待値の誤りかを人が判断する材料になる。

```markdown
| test_data_id | 観点 | 期待値の根拠 |
|---|---|---|
| 2026112109-01 | 仕様どおり: 表紙と 3 ページ | 計画書 2.1 |
| 2026112109-04 | 全角の ＃＃ | 仕様にない。見出しとして扱うのが自然 |
```

`test_data_id` は `YYYYMMDDhh-NN`（`NN` は 01 からの連番）にする。
